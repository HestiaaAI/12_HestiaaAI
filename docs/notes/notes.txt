Phase 0–1 implementation and Section 2 evidence — September 20, 2026

The submission uses Task for all four demonstrations. Each page reads Task rows,
searches titles through the GET parameter q, and renders the same inherited
Task-list template. The four links switch Python implementations, not business
actions. Matching results are intentional. Creating/editing/assigning/completing
work is outside this phase. Task is a reusable definition; occurrence dates and
progress belong to TaskOccurrence, and personal responses belong to Assignment.

View map (all routes are prefixed with http://127.0.0.1:8001 in the captures):

A01 | task_manual_view | Manual function-based view
URL: /tasks/manual/ | Name: workflows:task-manual
Queries Task, applies title search, loads tasks/task_list.html explicitly,
renders it with the request, and wraps the result in HttpResponse.
Screenshot: docs/screenshots/section-2/01-httpresponse.jpg

A02 | task_render_view | Shortcut function-based view
URL: /tasks/render/ | Name: workflows:task-render
Queries the same Task data and returns Django's render() shortcut.
Screenshot: docs/screenshots/section-2/02-render.jpg

A03 | TaskBaseView | Base class-based view, directly inherits View
URL: /tasks/cbv-base/ | Name: workflows:task-cbv-base
Its explicit get() method queries Task and renders the shared template.
Screenshot: docs/screenshots/section-2/03-base-cbv.jpg

A04 | TaskListView | Generic class-based view, inherits ListView
URL: /tasks/cbv-generic/ | Name: workflows:task-cbv-generic
Declares model=Task, template_name and context_object_name=tasks;
get_queryset() applies the same optional title search.
Screenshot: docs/screenshots/section-2/04-generic-cbv.jpg

Reproduce safely from the project root
Use the .venv environment configured in README.md. The following command creates
a NEW temporary SQLite database, applies migrations, optionally seeds fictional
tasks and starts the demo server. It never uses the project's db.sqlite3.
Stop with Ctrl-C. Run again in a second terminal with HESTIA_DEMO_MODE=empty for
the empty database on port 8002. Temporary databases are not submission files.

```bash
HESTIA_DEMO_MODE=populated .venv/bin/python - <<'PYDEMO'
import os
import tempfile
from pathlib import Path

mode = os.environ["HESTIA_DEMO_MODE"]
assert mode in {"populated", "empty"}
os.environ["DJANGO_SETTINGS_MODULE"] = "hestia_config.settings.development"
from django.conf import settings
settings.DATABASES = {"default": {
    "ENGINE": "django.db.backends.sqlite3",
    "NAME": Path(tempfile.mkdtemp(prefix="hestia-demo-")) / "db.sqlite3",
}}
import django
django.setup()
from django.core.management import call_command
call_command("migrate", interactive=False, verbosity=0)
if mode == "populated":
    call_command("seed_template_demo")
port = "8001" if mode == "populated" else "8002"
call_command("runserver", "127.0.0.1:" + port, use_reloader=False)
PYDEMO
```
